      Problematica del Mercado Gaming

      El mercado gamer enfrenta serios desafíos de accesibilidad y confiabilidad que afectan tanto a consumidores como vendedores especializados.

      Escasez De Tiendas Físicas

      Limitada disponibilidad de tiendas especializadas en productos gaming de calidad en territorio latinoamericano.

      🏪

      Acceso Limitado Productos

      Dificultad para encontrar productos especializados y componentes gaming específicos en el mercado local.

      🔎

      Compras Poco Confiables

      Usuarios recurren a páginas web poco confiables exponiendo sus datos personales y financieros.

      Requisitos Funcionales Y No Funcionales

      Documentacion Completa siguiendo el esquema IEEE, esto incluye todos los requisitos funcionales y no funcionales del sistema, como lo serian: Registrar usuarios, buscar en el catalogo de productos, poner una reseña etc.

      Requisitos Funcionales

      Requisito funcional 1:

      El sistema permitirá a los usuarios registrarse mediante un formulario con correo electrónico y contraseña, o utilizando cuentas de redes sociales como Google y Facebook. Deberá validar campos obligatorios, evitar duplicidad de cuentas y confirmar por correo electrónico.

      Requisito funcional 2:

      Las tiendas registradas podrán publicar, modificar o eliminar productos desde un panel de control. Cada producto deberá contener nombre, imagen, precio, descripción, disponibilidad y categoría.

      Requisito funcional 3:

      Los usuarios podrán buscar productos usando filtros por categoría, tienda, precio, popularidad y puntuación. La búsqueda debe responder rápidamente y ofrecer resultados relevantes.

      Requisito funcional 4:

      El sistema permitirá realizar compras mediante tarjeta de crédito/débito, PSE, billeteras digitales y otras pasarelas como PayU. Las transacciones deben ser seguras y generar comprobante.

      Requisito funcional 5:

      Los usuarios podrán valorar productos (con estrellas del 1 al 5) y escribir comentarios que serán visibles públicamente. El sistema debe moderar contenido ofensivo o fraudulento.

      Requisito funcional 6:

      Los usuarios podrán agregar múltiples productos al carrito, revisar el total, modificar cantidades o eliminar artículos antes de realizar la compra final.

      Requisito funcional 7:

      El sistema enviará notificaciones sobre promociones, confirmaciones de pedidos, mensajes de vendedores y cambios en el estado de las compras.

      Requisito funcional 8:

      Las tiendas dispondrán de un panel desde donde podrán gestionar sus productos, ver pedidos recibidos, actualizar estado de envíos, generar reportes de ventas y responder mensajes de clientes.

      Requisito funcional 9:

      Los usuarios podrán gestionar su perfil (nombre, dirección, contraseña, foto, etc.) desde una sección de configuración.

      Requisito funcional 10:

      Se permitirá la recuperación de contraseña por medio de correo electrónico con enlaces seguros y de uso único.

      Requisito funcional 11:

      El sistema soportará múltiples sesiones activas del mismo usuario en distintos dispositivos, con gestión de seguridad.

      Requisito funcional 12:

      Los usuarios podrán hacer seguimiento al estado de sus pedidos desde su perfil (procesando, enviado, entregado).

      Requisito funcional 13:

      Será posible cancelar pedidos que aún no hayan sido despachados, con reintegro automático si el pago ya fue realizado.

      Requisito funcional 14:

      Se habilitará un sistema de solicitudes de devolución y reembolso para compras realizadas, sujeto a políticas de cada tienda.

      Requisito funcional 15:

      Se integrará una sección de soporte al cliente con preguntas frecuentes, chatbot y formulario de contacto.

      Requisito funcional 16:

      Los usuarios podrán comparar características entre hasta 3 productos simultáneamente antes de comprarlos.

      Requisito funcional 17:

      El sistema permitirá guardar productos como favoritos para consulta posterior desde el perfil del usuario.

      Requisito funcional 18:

      En el checkout se podrán aplicar cupones de descuento vigentes, con validación automática y actualización del total.

      Requisito funcional 19:

      Los usuarios registrados acumularán puntos por compras, los cuales podrán canjear por descuentos o recompensas.

      Requisito funcional 20:

      Se permitirá compartir productos y comentarios directamente a redes sociales desde la plataforma.

      Requisito funcional 21:

      Las tiendas podrán gestionar su inventario desde el panel, recibiendo alertas por productos con bajo stock.

      Requisito funcional 22:

      Las tiendas podrán pagar para destacar productos en secciones visibles de la plataforma (publicidad interna).

      Requisito funcional 23:

      La aplicación móvil tendrá búsqueda por voz para facilitar la interacción desde dispositivos móviles.

      Requisito funcional 24:

      Solo los usuarios que hayan comprado un producto podrán dejar una reseña en el mismo (reseña verificada).

      Requisito funcional 25:

      El sistema incluirá una interfaz para la administración de categorías de productos, ordenamiento y subcategorías.

      Requisito funcional 26:

      Se guardará un historial de navegación, compras y búsquedas del usuario para personalizar la experiencia.

      Requisito funcional 27:

      El sistema utilizará la ubicación del usuario para mostrar productos relevantes y tiendas cercanas.

      Requisito funcional 28:

      Los usuarios podrán elegir qué tipo de notificaciones recibir (email, push, SMS) desde su configuración.

      Requisito funcional 29:

      Cada tienda podrá acceder a estadísticas de ventas, visitas a productos, e informes por periodo.

      Requisito funcional 30:

      Usuarios y tiendas podrán crear tickets para soporte técnico, con seguimiento del estado del caso.

      Requisito funcional 31:

      Se integrarán servicios de envío para mostrar costos y tiempos estimados de entrega al cliente.

      Requisito funcional 32:

      Se habilitará un modo oscuro que podrá activarse manualmente o según la configuración del sistema operativo.

      Requisitos No Funcionales

      Requisitos No Funcionales 1:

      El sistema deberá responder al 95% de las solicitudes en menos de 2 segundos, incluso bajo condiciones de carga moderada. Las operaciones críticas, como el inicio de sesión, búsqueda de productos y proceso de pago, deberán ejecutarse con fluidez para garantizar una experiencia de usuario rápida y eficiente. El rendimiento será monitoreado mediante herramientas de análisis y métricas de rendimiento en tiempo real.

      Requisitos No Funcionales 2:

      La plataforma implementará cifrado SSL/TLS para todas las comunicaciones y encriptación bcrypt para contraseñas de usuario. Se emplearán políticas de autenticación seguras, validación de sesiones, y control de permisos de acceso por rol. Además, se incluirán mecanismos de protección contra ataques comunes como SQL Injection, Cross-Site Scripting (XSS) y Phishing, garantizando la integridad y confidencialidad de los datos almacenados

      Requisitos No Funcionales 3:

      El sistema deberá garantizar una disponibilidad mínima del 99.5% mensual, excluyendo los periodos de mantenimiento programado. Se implementarán servidores escalables en la nube con balanceo de carga y copias de respaldo automáticas para asegurar la continuidad del servicio y la recuperación rápida ante fallos o caídas inesperadas.

      Requisitos No Funcionales 4:

      La aplicación deberá ser completamente funcional en navegadores modernos como Google Chrome, Mozilla Firefox y Microsoft Edge, además de sistemas operativos móviles Android e iOS. Será desarrollada con tecnologías multiplataforma (React, Node.js y Flutter), asegurando su correcto funcionamiento en diferentes dispositivos sin modificaciones extensas del código.

      Requisitos No Funcionales 5:

      El sistema deberá cumplir con las leyes 1581 de 2012 (protección de datos personales) y 527 de 1999 (comercio electrónico). Esto incluye la correcta gestión del consentimiento del usuario, el manejo seguro de la información personal y la implementación de políticas de privacidad y términos de uso claros y accesibles.

      Requisitos No Funcionales 6:

      La interfaz principal del sistema estará disponible en idioma español, adaptada al público latinoamericano. En futuras versiones, se podrá ampliar la compatibilidad multilingüe (inglés y portugués) para facilitar la expansión internacional de la plataforma.

      Requisitos No Funcionales 7:

      El código deberá estar documentado, modular y estructurado para facilitar su comprensión, depuración y mejora continua. Se utilizarán buenas prácticas de programación, control de versiones (Git), y pruebas automatizadas para reducir errores y asegurar la estabilidad del sistema durante futuras actualizaciones o expansiones.

      Requisitos No Funcionales 8:

      El sistema deberá registrar automáticamente eventos relevantes como accesos, errores, modificaciones de datos, y operaciones de pago en un módulo de auditoría interno. Estos registros estarán disponibles únicamente para administradores autorizados y servirán para la detección de incidentes de seguridad, trazabilidad de acciones y cumplimiento normativo.

              -- =========================
              -- SCRIPT TCL (Transaction Control Language)
              -- =========================
              -- Verificar que la base de datos existe antes de usarla
              USE gaming_center;
              
              -- MEJORAS IMPLEMENTADAS EN ESTE SCRIPT:
              -- 1. Generación automática de IDs únicos (order_number, payment_reference)
              -- 2. Manejo de errores de Foreign Key constraints  
              -- 3. Prevención de duplicados en campos UNIQUE
              -- 4. Validaciones previas antes de INSERT/UPDATE
              -- 5. Uso de ROW_COUNT() para verificar éxito de operaciones
              -- 6. Timestamps con microsegundos + Connection ID para unicidad
              -- 7. Sintaxis compatible con MariaDB (sin IF...THEN ni WHILE)
              -- 8. Operaciones idempotentes (ejecutables múltiples veces)
              
              -- Deshabilitar autocommit para control manual de transacciones
              SET autocommit = 0;
              -- Deshabilitar safe update mode temporalmente
              SET SQL_SAFE_UPDATES = 0;
              
              -- Ejemplo de transacción exitosa (crear pedido completo)
              START TRANSACTION;
              
              -- Verificar que el usuario y tienda existen
              SELECT @user_exists := COUNT(*) FROM users WHERE user_id = 1;
              SELECT @store_exists := COUNT(*) FROM stores WHERE store_id = 1;
              SELECT @product_exists := COUNT(*) FROM products WHERE product_id = 3;
              
              -- Generar número de pedido único usando timestamp
              SET @order_number = CONCAT('ORD-', DATE_FORMAT(NOW(), '%Y%m%d-%H%i%s'));
              
              -- Verificar que el número de pedido no existe
              SELECT @order_number_exists := COUNT(*) FROM orders WHERE order_number = @order_number;
              
              -- Calcular si podemos proceder (1 = sí, 0 = no)
              SET @can_proceed = (@user_exists > 0 AND @store_exists > 0 AND @product_exists > 0 AND @order_number_exists = 0);
              
              -- Solo insertar si todas las condiciones se cumplen
              -- Usar WHERE con la condición calculada
              INSERT INTO orders (user_id, store_id, order_number, status, total_amount)
              SELECT 1, 1, @order_number, 'processing', 350000.00
              WHERE @can_proceed = 1;
              
              -- Verificar si se insertó el pedido
              SELECT @rows_inserted := ROW_COUNT();
              
              -- Solo continuar si se insertó el pedido
              SET @new_order_id = LAST_INSERT_ID();
              
              -- Insertar items del pedido solo si el pedido fue creado
              INSERT INTO order_items (order_id, product_id, quantity, unit_price, subtotal)
              SELECT @new_order_id, 3, 1, 350000.00, 350000.00
              WHERE @rows_inserted > 0;
              
              -- Actualizar inventario solo si el pedido fue creado
              UPDATE inventory 
              SET stock = stock - 1
              WHERE product_id = 3 AND stock >= 1 AND @rows_inserted > 0;
              
              -- Verificar resultado y mostrar mensaje
              SELECT 
                CASE 
                  WHEN @rows_inserted > 0 THEN CONCAT('Pedido creado exitosamente: ', @order_number)
                  ELSE 'Error: No se pudo crear el pedido. Verificar condiciones.'
                END AS resultado;
              
              -- Confirmar cambios solo si todo fue exitoso
              COMMIT;
              
              -- Ejemplo de transacción revertida (manejo de errores)
              START TRANSACTION;
              
              -- Intentar actualizar inventario de producto existente
              UPDATE inventory 
              SET stock = stock - 5 
              WHERE product_id = 1 AND stock >= 5;
              
              -- Verificar si se afectaron filas
              SELECT ROW_COUNT() AS rows_affected;
              
              -- DEMOSTRACIÓN DE ERROR: Intentar insertar pago con order_id inexistente
              -- Este INSERT fallará intencionalmente para demostrar ROLLBACK
              -- Error esperado: 1452 - Cannot add or update a child row: foreign key constraint fails
              -- Descomenta la siguiente línea para probar el error:
              -- INSERT INTO payments (order_id, payment_method, payment_reference, amount, status)
              -- VALUES (999, 'Tarjeta', 'REF999', 200000.00, 'approved');
              
              -- Alternativa segura: verificar que existe el pedido antes de insertar
              SELECT COUNT(*) INTO @order_exists FROM orders WHERE order_id = 1;
              
              -- Generar referencia única para evitar duplicados
              SET @unique_payment_ref = CONCAT('REF-TCL-', UNIX_TIMESTAMP(), '-', CONNECTION_ID());
              
              -- Insertar pago solo si el pedido existe
              -- Usar WHERE en lugar de IF...THEN
              INSERT INTO payments (order_id, payment_method, payment_reference, amount, status)
              SELECT 1, 'Tarjeta', @unique_payment_ref, 200000.00, 'approved'
              WHERE @order_exists > 0;

              -- =========================
              -- SCRIPT DQL (Data Query Language)
              -- =========================
              -- Verificar que la base de datos existe antes de usarla
              USE gaming_center;
              
              -- Consultar todos los productos con inventario disponible
              SELECT p.product_id, p.name, i.stock
              FROM products p
              JOIN inventory i ON p.product_id = i.product_id
              WHERE i.stock > 0
              ORDER BY i.stock DESC;
              
              -- Consultar pedidos por cliente con JOIN
              SELECT o.order_number, u.email AS cliente, o.total_amount, o.status
              FROM orders o
              JOIN users u ON o.user_id = u.user_id
              WHERE u.role = 'customer';
              
              -- Consultar ingresos totales por tienda
              SELECT s.store_name, SUM(o.total_amount) AS total_ventas
              FROM stores s
              JOIN orders o ON s.store_id = o.store_id
              GROUP BY s.store_id
              HAVING total_ventas > 1000000;
              
              -- Subconsulta: productos sin reseñas (mejorada para manejar NULL)
              SELECT p.name, p.price
              FROM products p
              WHERE p.product_id NOT IN (
                SELECT DISTINCT r.product_id 
                FROM reviews r 
                WHERE r.product_id IS NOT NULL
              );
              
              -- Top 3 productos más caros
              SELECT name, price, currency
              FROM products
              ORDER BY price DESC
              LIMIT 3;
              
              -- Consulta adicional: productos con inventario bajo
              SELECT p.name, i.stock, i.minimum_stock
              FROM products p
              INNER JOIN inventory i ON p.product_id = i.product_id
              WHERE i.stock <= i.minimum_stock
              ORDER BY i.stock ASC;

              -- =========================
              -- SCRIPT VDL (View Definition Language)
              -- =========================
              -- Verificar que la base de datos existe antes de usarla
              USE gaming_center;
              
              -- Vista de productos con inventario (mejorada con más información)
              CREATE OR REPLACE VIEW view_products_inventory AS
              SELECT 
                p.product_id, 
                p.name, 
                p.price, 
                p.currency,
                i.stock, 
                i.minimum_stock,
                CASE 
                  WHEN i.stock = 0 THEN 'Sin stock'
                  WHEN i.stock <= i.minimum_stock THEN 'Stock bajo'
                  ELSE 'Stock normal'
                END AS stock_status
              FROM products p
              INNER JOIN inventory i ON p.product_id = i.product_id;
              
              -- Vista de clientes con sus pedidos
              CREATE OR REPLACE VIEW view_customer_orders AS
              SELECT u.email, o.order_number, o.status, o.total_amount, o.created_at
              FROM users u
              JOIN orders o ON u.user_id = o.user_id
              WHERE u.role = 'customer';
              
              -- Vista de ingresos por tienda (mejorada)
              CREATE OR REPLACE VIEW view_sales_by_store AS
              SELECT 
                s.store_id,
                s.store_name, 
                COUNT(o.order_id) AS total_orders,
                SUM(o.total_amount) AS total_ventas,
                AVG(o.total_amount) AS promedio_venta
              FROM stores s
              LEFT JOIN orders o ON s.store_id = o.store_id
              GROUP BY s.store_id, s.store_name;
              
              -- Vista de productos con promedio de reseñas (corregida)
              CREATE OR REPLACE VIEW view_products_reviews AS
              SELECT 
                p.product_id,
                p.name, 
                COUNT(r.review_id) AS total_reviews, 
                COALESCE(ROUND(AVG(r.rating), 2), 0) AS avg_rating,
                s.store_name
              FROM products p
              LEFT JOIN reviews r ON p.product_id = r.product_id
              INNER JOIN stores s ON p.store_id = s.store_id
              GROUP BY p.product_id, p.name, s.store_name;
              
              -- Recrear la vista de ventas por tienda (para demostrar DROP y CREATE)
              DROP VIEW IF EXISTS view_sales_by_store;
              
              -- Crear vista de resumen de ventas por tienda
              CREATE VIEW view_sales_by_store AS
              SELECT 
                s.store_id,
                s.store_name, 
                COUNT(o.order_id) AS total_orders,
                COALESCE(SUM(o.total_amount), 0) AS total_ventas,
                COALESCE(AVG(o.total_amount), 0) AS promedio_venta
              FROM stores s
              LEFT JOIN orders o ON s.store_id = o.store_id
              WHERE o.status NOT IN ('cancelled', 'returned') OR o.status IS NULL
              GROUP BY s.store_id, s.store_name;

      VDL (View Definition Language) → creacion de vistas basadas en la estructura y datos ya cargados.

      1. Definir vistas para consultas especializadas
      2. Consultar vistas como si fueran tablas
      
              -- =========================
              -- SCRIPT DQL (Data Query Language)
              -- =========================
              -- Verificar que la base de datos existe antes de usarla
              USE gaming_center;
              
              -- Consultar todos los productos con inventario disponible
              SELECT p.product_id, p.name, i.stock
              FROM products p
              JOIN inventory i ON p.product_id = i.product_id
              WHERE i.stock > 0
              ORDER BY i.stock DESC;
              
              -- Consultar pedidos por cliente con JOIN
              SELECT o.order_number, u.email AS cliente, o.total_amount, o.status
              FROM orders o
              JOIN users u ON o.user_id = u.user_id
              WHERE u.role = 'customer';
              
              -- Consultar ingresos totales por tienda
              SELECT s.store_name, SUM(o.total_amount) AS total_ventas
              FROM stores s
              JOIN orders o ON s.store_id = o.store_id
              GROUP BY s.store_id
              HAVING total_ventas > 1000000;
              
              -- Subconsulta: productos sin reseñas (mejorada para manejar NULL)
              SELECT p.name, p.price
              FROM products p
              WHERE p.product_id NOT IN (
                SELECT DISTINCT r.product_id 
                FROM reviews r 
                WHERE r.product_id IS NOT NULL
              );
              
              -- Top 3 productos más caros
              SELECT name, price, currency
              FROM products
              ORDER BY price DESC
              LIMIT 3;
              
              -- Consulta adicional: productos con inventario bajo
              SELECT p.name, i.stock, i.minimum_stock
              FROM products p
              INNER JOIN inventory i ON p.product_id = i.product_id
              WHERE i.stock <= i.minimum_stock
              ORDER BY i.stock ASC;
